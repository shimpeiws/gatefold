# Gatefold v0.11 scope: analyze evidence boundary and 1.0 readiness

**Status: implemented (v0.11; issues #86–#89 under milestone #12).**
v0.11 ships no new command. It draws the boundary between Gatefold's
evidence surface and the separate `analyze` contract-evaluation layer,
settles the v0.7 evaluation commands' ownership, and writes the 1.0
public contract and release gate.

## What v0.11 adds

| Piece | Where | Notes |
| --- | --- | --- |
| Versioned evidence-accessor contract for analyze | [analyze-accessor-contract.md](analyze-accessor-contract.md) | Accessor contract v1 over result schemas v8/v9/v10 — field selectors, evidence-source → file mapping, state vocabulary, Case A accessor table. No Gatefold Contract/predicate DSL is introduced. |

## Boundary

Gatefold owns source validation, identity binding, completeness, audit
states, and descriptive comparison. `analyze` owns contract admission and
verdicts. Gatefold never emits `satisfied`/`violated` and never answers a
consumer's proposition; the v6/v7 `pass`/`fail`/`unknown` surface is a
deprecated compatibility lane, and supplied v6/v7 documents remain
bindable in `report-cell`/`compare-cells` as labelled supplied legacy
verdicts.

Existing behavior is unchanged except for the additive
`observationReason` field and the deprecation markings; every
v0.1–v0.10 command, schema, and exit code keeps working.
