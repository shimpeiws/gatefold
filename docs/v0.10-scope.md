# Gatefold v0.10 scope and repeated-cell report contract

**Status: implemented (v0.10; issue #85).**
v0.10 adds `report-cells`: one evidence-backed account of a **bounded set
of repeated yuurei cells** supplied as explicit run directories. For the
supplied set the report states which configuration facts were observed in
each run, which records differed, and which could not be checked — counts
run over *eligible observations* with a named denominator, evidence
resolvable into each retained export, and every per-run lane a
single-cell report carries. It never issues a stability verdict, a causal
reading, a ranking, or a generalization beyond the supplied runs.

It builds on the
[run-directory contract](yuurei-run-contract.md), the
[trace contract](yuurei-trace-contract.md), the
[pfl document contract](pfl-export-contract.md), the
[audit contract](v0.8-scope.md), and the
[v0.9 cell-report contract](v0.9-scope.md); all of their invariants are
unchanged. In particular: the runs are never executed, never discovered
implicitly, and each is validated through the existing manifest/digest,
binding, and document contracts.

## CLI surface

```text
gatefold report-cells --run <run-dir-1> --run <run-dir-2> [--run <dir>] ...
                      [--format human|json]
```

| Rule | Contract |
| --- | --- |
| `report-cells` inputs | `--run` is repeatable and names one yuurei run directory per occurrence. Between **2 and 32** runs are accepted; the report labels them `run1`…`runN` in argument order. One run is a usage error — that is `report-cell`. More than 32 is an input error (the bounded-set ceiling). |
| Supplied set | The set is exactly the supplied directories, in order. Runs are never discovered, globbed, or executed. |
| Duplicates | The same directory supplied twice — under any spelling that resolves to the same path — is a usage error. Two *distinct* directories recording the same `run_id` or `cell_id` are **not** an error: `set.identities` states the duplicate identity as a recorded fact. |
| Stdin | `-` is rejected as a flag value with a usage error, as in the other directory commands. |
| `--evaluation` | `report-cells` accepts **no** evaluation input: the v6/v7 supplied-context contracts are single-run/pairwise, so the flag is unknown here (usage error). |
| `--min-confidence` | Rejected with a usage error, as on every cell-report command — entries carry no confidence. |
| Options / exit codes | `--format` and `--help` behave as elsewhere. Exit codes unchanged: 0 success, 2 usage error, 3 input error, 4 internal error. |
| Existing forms | Every v0.1–v0.9 command, schema, and exit code is unchanged. |

## Grouping: one comparable set, or rejection

`report-cells` reports exactly one set. A set is admitted only when the
same comparability conditions hold **uniformly across all supplied
traces** as `compare-cells` enforces pairwise
(`requested_cell.inputs_version`, `task.digest`, `runtime.id`,
`model.requested`, `isolation.strategy`, `execution_options` — with the
same "all traces record the field" requirement for `requested_cell` and
`execution_options`, which otherwise produce caveats). The first
non-uniform gated field rejects the whole set with `mismatched-inputs`
(exit 3), naming the run pair the check failed on — the set is never
partitioned silently into compatible subgroups.

Observed-property drift (yuurei version, runtime version, resolved model,
resolved-model reason, isolation verification) becomes `set.caveat.*`
entries, exactly as `compare-cells` records them.

Source-project identity gates the set the same way it gates a pair: the
*declared* identities are collected from every trace's
`seed.source_project` and every bound export's
`data.snapshot.sourceProject`. More than one distinct declared `id` in
the set rejects `mismatched-inputs` — the runs do not record one source
project. One declared id joins the set only when **every bound run
verifies it** — its own trace seed record and its own bound export agree
on that id (the v9 per-side rule). A bound run that declares nothing, or
whose records disagree, cannot be shown to describe the declared source:
unless all bound exports' observed `data.project.id` values are equal
anyway, the account is withheld. With no declared identity at all, the
observed `data.project.id` values alone decide: all equal → the set
proceeds over the observed identity; any difference →
`set.config-unavailable` (whether the set shares one source project is
unverifiable — never a false match, never a rejection the records cannot
support). The bound exports' `data.runtime.id` values must also be
uniform, as `compare-cells` requires.

A profile content-digest difference is not drift and not a rejection:
`set.profile` states each distinct digest/name as context.

## What is counted, and against what

Every repeated-observation statement distinguishes three populations:

| Population | Meaning |
| --- | --- |
| supplied runs | The N directories named by `--run`. |
| bound exports | Runs whose `association.export-binding` is `verified` — the retained export parses and records this cell's `cell_id`. |
| eligible observations | The bound exports counted into "K of E" denominators. An unbound run — no observation record, export undeclared or unretained, bytes failed or truncated, document unparsable, `cellId` null/mismatched, `cell_id` unrecorded — contributes **zero** to E and its state is always reported as *unknown*, never as absence or sameness. |

`set.inputs` states all three numbers and names the ineligible runs.

An element (relation, finding) is reported as **recorded in K of E
eligible exports**. A run's complete export that omits the element is a
recorded non-observation; a *partial* export that omits it leaves the
absence unestablished — the statement says so. An element's *content* is
grouped across eligible exports by pfl `diff` identity
(`observed.native.kind`, `observed.native.scope`, `observed.source.digest`,
canonical `observed.metadata`): identical content in every eligible export
that records it is stated as "identical", differing content is stated
naming which runs share each form — never a verdict that a difference is
meaningful. Resolved-layer facts keep the absent-vs-null-vs-valued
vocabulary: `resolved: null` is "no resolved layer recorded", and an
element unrecorded in an export is never read as `resolved: null`.

`set.config-unavailable` replaces all per-element/relation/finding
entries when fewer than two bound exports exist or no shared identity is
established — the report names the reason and emits nothing that could
be read as "no recorded difference".

## Lanes and entries

Every entry carries a `lane`, and a `subject` of `run1`…`runN` when it
describes one run:

| Lane | Content |
| --- | --- |
| `association`, `configuration`, `execution`, `audit` | Per run, exactly the checks and content v0.9's `report-cell` emits (subject `runN`). No `evaluation` lane exists in v10. |
| `set` | The repeated-set account (no subject): the three population counts, set-wide comparability, drift caveats, requested-cell and profile context, recorded-identity distinctness, the shared source identity, and the per-record statements — `set.element.<id>` for each element id in the union (byte order), `set.relation.<n>` and `set.finding.<n>` for each distinct relation/finding in the union (v9 ordering keys). |

Set-level entry ids, in order: `set.inputs`, `set.comparability`,
`set.caveat.<field>`, `set.requested-cell`, `set.profile`,
`set.identities`, `set.source-identity`, `set.elements`, then the
per-record entries, or `set.config-unavailable` when the configuration
account is withheld.

Evidence sources are run-indexed: `run1Trace`, `run2Export`,
`run3BaselineManifest`, … — the v0.9 base names prefixed with the run's
label, resolving into that run's documents under the same rules.

## Determinism and limits

Entry order: by subject (`run1`…`runN`, set entries last), then lane
(`association`, `configuration`, `execution`, `audit`, `set`), then each
lane's stable order. Evidence sorts by run index, then the v0.9 base
source order, then pointer byte order. Reordering `--run` arguments
relabels the runs; the same set in the same order produces byte-identical
output. The shared entry/evidence ceilings and all input byte/size/path
limits apply unchanged.

## Vocabulary and prohibitions

Same as v0.9, plus: a repeated-run statement's denominator is always the
eligible-observation count, never "the runs" loosely; "the eligible
observed records in the supplied set match" is the strongest agreement a
record can earn. Prohibited: stability or flakiness judgements,
extrapolation beyond the supplied set, causal attribution, ranking, and
reading any unknown, unbound, or partially-observed record as absence,
removal, or unchanged.

## Case matrix

Derived expectations; unknown or absent layers never become positive or
negative assertions.

| Case | Expected |
| --- | --- |
| one `--run` / none | usage error (exit 2) |
| `--run -` | usage error (exit 2) |
| `--min-confidence`, `--evaluation` | usage error (exit 2) |
| 33 runs | input error (exit 3) |
| same directory supplied twice (any spelling) | usage error (exit 2) |
| distinct directories, same recorded `run_id`/`cell_id` | admitted; `set.identities` states the duplicate as a recorded fact |
| `task.digest`/`runtime.id`/`model.requested`/`isolation.strategy`/`execution_options`/`inputs_version` differ on any run | `mismatched-inputs`, exit 3, naming the failing pair |
| `requested_cell`/`execution_options` absent on some run | `set.caveat.*` records the gap; `set.comparability` claims only the checked fields (`recorded`/`partial`, never `verified` on unchecked gates) |
| yuurei/runtime version, resolved model, isolation.verified differ | `set.caveat.*`, continue |
| two runs declare different `source_project.id` | `mismatched-inputs`, exit 3 |
| profile digest differs | `set.profile` states both digests; never a rejection |
| all runs bound, shared verified declared source, observed project ids differ | `set.source-identity` verified; per-record entries emitted |
| one declared source, some bound run does not verify it, observed `project.id`s differ | `set.source-identity` unverifiable; `set.config-unavailable`; no per-record entries |
| one declared source not verified on every bound run, but observed `project.id` all equal | admitted on the observed identity; `set.source-identity` still states the unverified declaration |
| no declared identity, observed `project.id` all equal | `set.source-identity` recorded (observed); per-record entries emitted |
| no declared identity, observed `project.id` differ | `set.source-identity` unverifiable; `set.config-unavailable`; no per-record entries |
| bound exports' `data.runtime.id` differ | `mismatched-inputs`, exit 3 |
| fewer than 2 bound exports | `set.config-unavailable`; no per-record entries; per-run lanes unaffected |
| a run unbound (unavailable/absent/failed/unbound export) | excluded from E; every set entry names it as not checked; per-run lanes report its own records |
| element identical across all eligible exports | "recorded in E of E eligible exports; identical observed content" — eligible-observation agreement only |
| element content differs | entry names which runs share each form |
| element present in some eligible exports | K-of-E statement naming the recording runs; a partial export's omission is an unestablished absence |
| `resolved: null` on one run, status on another | "no resolved layer recorded" vs the recorded status, named per run |
| relations/findings in a subset | K-of-E membership per union member |
| `partial` completeness export in the set | set entries' completeness downgraded to `partial` |
| reordered `--run` args | runs relabelled in argument order; set membership identical |
| same set, same order | byte-identical output |

| Fixture | Case |
| --- | --- |

## Versioning

`schemaVersion: 10`, `source.command: "report-cells"`, schema
`claim-result.v10.json`. v0.1–v0.9 schemas and commands are untouched.

Additive under the same version: each run input descriptor carries the
same optional `observationReason` field v9 adds — see
[the analyze accessor contract](analyze-accessor-contract.md).
