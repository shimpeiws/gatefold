# Gatefold v0.9 scope and cell-report contract

**Status: implemented (v0.9; issues #77–#80 under milestone #76).**
v0.9 adds a **cell report**: one evidence-backed account of a yuurei run
directory that also ingests the pre-run pfl observation the run's trace and
manifest declare. `report-cell` presents one cell; `compare-cells` presents
a directional A → B account of two compatible cells. Every statement is
tied to a named input — the trace, the artifact manifest, a retained
artifact's verified bytes, a verified pfl export document, or a supplied
gatefold evaluation result — and carries an explicit state and
completeness. Nothing here attributes outcomes to causes, ranks cells, or
invents a judgement: the report describes what each record declares and
where the records agree, disagree, or run out.

It builds on the
[run-directory contract](yuurei-run-contract.md), the
[trace contract](yuurei-trace-contract.md), the
[pfl document contract](pfl-export-contract.md), and the
[audit contract](v0.8-scope.md); all of their invariants are unchanged.

## CLI surface

```text
gatefold report-cell  --run <run-dir>
                      [--evaluation <v6-evaluation-result.json>]
                      [--format human|json]

gatefold compare-cells --before <run-dir-A> --after <run-dir-B>
                       [--evaluation <v7-evaluation-comparison-result.json>]
                       [--format human|json]
```

| Rule | Contract |
| --- | --- |
| `report-cell` inputs | `--run` names one yuurei run directory. `--evaluation` is optional and names one gatefold v6 `evaluate-run` result document, presented as labelled supplied context. |
| `compare-cells` inputs | `--before`/`--after` name the A and B run directories. `--evaluation` is optional and names one gatefold v7 `compare-evaluations` result document. |
| Stdin | Directories and supplied documents cannot arrive on stdin: `-` is rejected as a flag value with a usage error. |
| Existing forms | Every v0.1–v0.8 command, schema, and exit code is unchanged. |
| Options / exit codes | `--format` and `--help` behave as in the existing forms. `--min-confidence` is **rejected** with a usage error (exit 2) on both cell commands: report entries carry no confidence, so the filter cannot apply and silently ignoring it would mislead a caller into believing the output was filtered. (`audit-run` keeps its v0.8 behaviour of accepting the option and applying nothing, which v0.8's contract documents.) Exit codes unchanged: 0 success, 2 usage error, 3 input error, 4 internal error. |

## What a cell is

A **cell input** is one yuurei run directory plus the pfl observation
export the run's own records declare. Concretely:

- `trace.json` optionally carries `cell_id` — the identifier of the
  prepared cell instance — and an optional `observation` record
  (yuurei ADR-0022): `{ observer: { id, version|null }, status:
  "recorded" | "partial" | "unavailable", reason: <enum> | null,
  completeness: string | null, snapshot_ids: { observed, resolved } |
  null, artifacts: [{ path, kind }] }`.
- `artifacts.json` may list the observation artifact paths the trace
  declares, each with the manifest's digest over the stored bytes.
- The **pfl export artifact** is the one declared path the contract
  defines: `observation/export.json`. It is the only observation artifact
  the shipped observer ever records, and it is a `pfl export --json`
  document (envelope `pflVersion`, `command: "export"`, `ok`,
  `completeness`, `diagnostics`, `data`; `data.snapshot` adds `cellId:
  string | null` in pfl v1.2.0 — a caller-asserted value copied from
  `--cell-id`, not a property pfl verified).

Identity boundaries the report never blurs:

| Name | What it identifies |
| --- | --- |
| `run_id` | The retained run directory's trace record. |
| `cell_id` | The prepared cell instance the run executed in; absent on runs where observation or cells were not opted in. Not part of `requested_cell.digest`. |
| `requested_cell.digest` | The requested input set; two cells prepared from the same request share it. |
| `data.snapshot.observedSnapshotId` | The pfl snapshot identity of what was observed. |
| `data.snapshot.resolvedSnapshotId` | The pfl snapshot identity of the resolved view. |
| `data.snapshot.cellId` | The caller-asserted cell association stamped into the export. |

## Recorded association, not complete visibility

A matching `cell_id` (trace `cell_id` equals the verified export's
`data.snapshot.cellId`) establishes a **recorded association**: the run's
own records and the export both name the same prepared cell, and the
retained bytes hash to the digest the manifest recorded. It does **not**
prove that every runtime layer was observed, that a statically effective
element was used by the agent, that the observer saw the complete
harness, or that the export was produced against this cell rather than
stamped by a caller. pfl itself documents `cellId` as caller-asserted.

Observation status and completeness are independent dimensions and stay
separate: `recorded`/`partial`/`unavailable` say what the observer
reported; the export's own `completeness` says how complete that document
is; a truncated or corrupt artifact is a storage fact. An absent
`observation` record means observation was not recorded — it never means
"no configuration", and a `partial` or `unavailable` status never means
`recorded`.

## Resolving the export artifact

The export artifact is resolved **only** through the run's own records:

1. The trace's `observation.artifacts` declares retained paths. The
   export is the entry at the fixed path `observation/export.json`.
   Other declared paths (bundle files, foreign names) are reported as
   declared facts and never interpreted as the export.
2. The manifest must list the declared path; bytes are verified against
   the manifest digest under the existing confinement, symlink, and size
   boundaries. A trace-declared path the manifest does not list is not
   retained.
3. Only untruncated digest-verified bytes are parsed, and only a
   document that parses as a `pfl export` document (`command: "export"`,
   `ok: true`, contract-valid shape, supported pfl version) is
   interpreted.

Never: pick a file by timestamp, a file name pattern such as `latest`, a
directory scan of `observation/`, or a path declared *inside* the pfl
document or any other untrusted document.

Distinct states preserved, each reportable:

| State | Condition |
| --- | --- |
| not recorded | `observation` record absent, or present with `status: "unavailable"` and no artifacts declared |
| declared, not retained | trace declares `observation/export.json` but the manifest does not list it |
| retained, failed | manifest entry exists; file missing, digest mismatch, oversize, or symlink escape |
| retained, truncated | bytes verify to a `truncated: true` entry — never treated as a complete document |
| verified, unparsable | verified untruncated bytes that are not a valid pfl export document |
| verified, bound | valid export whose `cellId` equals `trace.cell_id` |
| verified, contradicted | valid export whose `cellId`, snapshot ids, or runtime contradict the trace record |

Only an export the run's **own observation record declares** is read as the
run's observed configuration: when the trace records no `observation`, or its
record does not declare `observation/export.json`, every `export.*`
association check is `not-recorded` and no configuration is published — a
manifest-listed artifact no record declares stays a reportable manifest fact
and a `record-consistency` contradiction, never this run's configuration.

Declaration also governs *reading*: an undeclared manifest entry is never
opened or digest-verified, so a missing, escaping or otherwise unreadable
artifact at that path cannot reject the report — the contradiction is
reported instead. The input descriptor follows the same rule: it carries the
export's snapshot ids only when the binding is `verified`, so an unbound
export's ids are never presented as this cell's identity.

A valid export that omits the `data.snapshot.cellId` key entirely (pfl before
v1.2.0, or an authored record) is `verified` but **unbound**: the association
is `unverifiable`, never a report failure, and the entry cites the
`data.snapshot` object it could resolve with a note naming the absent key.
A recorded export is also a retention claim: a `recorded`/`partial`
observation whose declared export the manifest does not list is a
contradiction (`inconsistent`), not merely an unretained artifact.

## Cross-record checks

The association lane runs a fixed set of mechanical checks (all emitted
even when `not-recorded`):

| Check id | Statement |
| --- | --- |
| `association.cell-id` | Whether the trace records `cell_id`. |
| `association.observation` | Whether an `observation` record exists and its declared status/reason. |
| `association.export-retained` | Whether the trace-declared export path is manifest-listed and its stored bytes verify. |
| `association.export-document` | Whether the verified export bytes parse as a conforming `pfl export` document. |
| `association.export-binding` | Whether `data.snapshot.cellId` equals `trace.cell_id`. Equal → `verified`; both present and unequal → `inconsistent`; export `cellId` null or absent, or `trace.cell_id` absent → `unverifiable`; no verified export → `not-recorded`. |
| `association.export-snapshots` | Whether `observation.snapshot_ids` equals the export's `observedSnapshotId`/`resolvedSnapshotId`. `snapshot_ids` null → `unverifiable` (the observer did not record them). |
| `association.export-runtime` | Whether `data.runtime.id` equals `trace.runtime.id`. |
| `association.export-completeness` | Whether `observation.completeness` equals the export `completeness` when both are recorded. |
| `association.record-consistency` | Whether the record is internally coherent: `unavailable` must not declare artifacts; `recorded`/`partial` must declare and retain the export path; a non-`observation`-conforming declared path is a contradiction. |

## Evidence lanes

Every entry carries a `lane` naming the record family it reports:

| Lane | Content |
| --- | --- |
| `association` | The fixed cross-record checks above. |
| `configuration` | What the bound export declares: snapshot identity and completeness, per-element observed status, resolved status, and interpretation facets/confidence, relations, findings, diagnostics. Emitted only when the binding is `verified`; otherwise one availability marker states why no configuration is presented. A `partial` export yields `partial`-completeness entries; unobserved layers stay unobserved. |
| `execution` | What the run records: run id, task, profile, runtime, model, requested cell, isolation, execution outcome, usage, cost, retained artifacts, result and patch records, diagnostics. |
| `audit` | The v0.8 audit facts for the same loaded run, re-identified under this result's sources; states and completeness are unchanged. |
| `evaluation` | The supplied evaluation result's verdicts — presented verbatim, labelled as supplied context, only when the document is a **conforming** gatefold result (`evaluate-run` v6 for a single cell, `compare-evaluations` v7 for a comparison, each with its own required records: inputs, run context, and per-criterion evidence and provenance) *and* its recorded `run`/`before`/`after` inputs bind to this run (run id and task digest equal). A document that does not conform, or that is of the other kind, is reported as unusable context; a conforming document whose identity is mismatched is reported as an `inconsistent` binding. Neither presents verdicts as this cell's. |
| `comparison` | A/B only: directional statements below. |

## A → B comparison

`compare-cells` accepts the pair only when the v0.5 trace comparability
rules hold (`requested_cell.inputs_version`, `task.digest`, `runtime.id`,
`model.requested`, `isolation.strategy`, `execution_options`), so the
same rejections apply with the same exit code. Observed-property drift
(yuurei version, runtime version, resolved model, isolation verification)
becomes comparison caveats, as does a profile identity difference, which
is the subject of the comparison rather than a defect.

The configuration difference is computed only from **bound** exports: a
side whose `association.export-binding` is anything other than `verified`
(absent, unretained, unparsable, `cellId` mismatched or null, `cell_id`
unrecorded) has no verified configuration to compare, so the comparison
emits `comparison.config-unavailable` naming that side's binding state
and withholds every element/relation/finding difference — never "no
configuration change". When both cells present bound exports, the
exports must describe the same `data.project.id` and
`data.runtime.id`; a mismatch rejects with `mismatched-inputs` — the same
rule `compare` applies between export documents.

Directional statements reuse pfl's diff semantics computed from the two
verified exports (there is no pfl diff document in a run):

- **structural**: element ids added in B, removed in B, or changed —
  where *changed* means the same element id with a different
  `observed.native.kind`, `observed.native.scope`, `observed.source.digest`,
  or canonically-serialized `observed.metadata` (pfl `diff` semantics);
- **effective**: per-id resolved-status transitions (`from`/`to`),
  `newly effective` / `no longer effective` / `activation changed`
  counts over the union of resolved elements;
- **facets**: per-facet interpretation count deltas;
- **relations / findings**: set differences — a reworded finding is an
  add plus a remove;
- **execution/usage/cost**: the recorded A and B values side by side,
  with the same absent-versus-null rules as `compare-runs`;
- **output**: patch file sets added/removed/changed, and the result
  record state on each side. Two blocks are identical only when their
  stored block bytes are byte-equal — the block's headers carry the edit
  positions, so equal `+`/`-` content at different positions is a
  *changed* file, not an identical one. A file-set difference is asserted only when
  both sides' patch records are complete change records (the audit's
  `patch.completeness` being `verified`); otherwise one
  `comparison.patch` entry reports each side's patch state and the counts
  *within the retained patches* with `partial`/`unknown` completeness,
  and no per-file entry is emitted — a file a partial record omits is
  never read as a deletion.

Caveats instead of content: when a side's observation is absent,
unavailable, partial, unretained, or unbound, the comparison lane says
the configuration difference **cannot be reported** — it never concludes
"no configuration change". A partial, truncated or uncertified patch on
either side removes the file-set difference the same way.

## Entry model (schema v9)

Every entry:

| Field | Meaning |
| --- | --- |
| `lane` | One of the lanes above. |
| `subject` | `compare-cells` only: `"before"` or `"after"` for the cell the entry describes; absent on `comparison` entries and in single-cell results. |
| `id` | Stable dot-separated identifier. Closed per lane, extended only additively. |
| `state` | `verified`, `inconsistent`, `unverifiable`, `not-recorded` (the cross-check outcomes), or `recorded` (a document declares this — used for configuration, execution, supplied-evaluation, and comparison content). |
| `completeness` | `complete`, `partial`, `unknown` — same dimension as v0.8. |
| `statement` | A descriptive account of what the record declares or what the check established. |
| `evidence` | References into named inputs; every pointer resolves inside its document, `digest` repeats verified stored digests, `elementId` names the export element cited. |
| `provenance` | `{ transform: ["<command>", "entry:<id>"] }` — report builders and fact ids only. |

### Evidence sources

Single cell: `trace`, `manifest`, `export`, `patch`, `result`,
`baselineManifest`, `changes`, `evaluation`. A/B: the same names with
`before`/`after` prefixes (`beforeTrace`, `afterExport`, …).

| Source | Pointer target |
| --- | --- |
| `trace` | JSON Pointer into `trace.json`. |
| `manifest` | JSON Pointer into `artifacts.json` (entries are `/artifacts/<i>`). |
| `export` | JSON Pointer into the digest-verified export document; `digest` carries the manifest digest binding the citation to retained bytes. |
| `patch` / `result` | `/artifacts/<i>` naming the manifest entry, plus `path`/`lines`/`bytes` inside verified bytes. |
| `baselineManifest` / `changes` | JSON Pointer into the verified record document. |
| `evaluation` | JSON Pointer into the supplied evaluation result document. |

## Determinism and limits

Entries are emitted in a fixed order — subject (`before` before `after`),
then lane order (`association`, `configuration`, `execution`, `audit`,
`evaluation`, `comparison`), then a stable per-lane order (fixed check
ids in listed order; element/relation/finding entries in pfl's byte-order
key ordering). Evidence is sorted by a fixed source order then pointer
byte order. The same entry/evidence ceilings as the comparison commands
apply, plus the shared input byte/size/path limits.

## Vocabulary and prohibitions

Statements describe records: "records", "declares", "matches", "does not
record", "cannot be verified", "was added/removed/changed between the two
retained exports". Prohibited everywhere:

- causal attribution ("because", "caused", "due to" an element or
  profile);
- ranking or quality judgement ("better", "worse", "regression", "win");
- inferring that a statically effective element was used at runtime;
- turning an absent, failed, or partial observation into a "no change"
  or "no configuration" claim.

## Case matrix

Derived expectations; unknown or absent layers never become positive or
negative assertions.

### Single-cell association

| Case | Expected |
| --- | --- |
| `cell_id` absent | `association.cell-id` not-recorded; binding unverifiable; configuration withheld |
| `cell_id` present, `observation` absent | `association.observation` not-recorded; all `export.*` not-recorded; `configuration.availability` not-recorded (a manifest-listed export stays a manifest fact only); execution/audit lanes unaffected |
| `observation` present but declares no export path | all `export.*` not-recorded; `record-consistency` inconsistent when the manifest retains the path; configuration withheld; the path is never opened |
| no `observation` record but the manifest lists `observation/export.json` | `record-consistency` inconsistent (an unobserved run must not retain an observation artifact); the artifact is never opened |
| an export that parses but is not bound | `inputs.run.exportObservedSnapshotId`/`exportResolvedSnapshotId` are `null`; configuration withheld |
| a patch or result artifact whose stored bytes are not verified | its execution-lane entry cites the manifest entry, not stored bytes |
| `observation.status: "unavailable"`, reason recorded, no artifacts | `association.observation` recorded; `export.*` not-recorded; `record-consistency` verified; no configuration claim |
| `status: "recorded"`/`"partial"` but no `export.json` declared | `record-consistency` inconsistent; `export-retained` not-recorded |
| `status: "unavailable"` but artifacts declared | `record-consistency` inconsistent |
| export declared, manifest entry absent | `export-retained` unverifiable (declared, not retained); `record-consistency` inconsistent (`recorded`/`partial` asserts a retained export); no parsing |
| manifest entry present, file missing | `export-retained` unverifiable |
| digest mismatch / oversize / truncated | `export-retained` unverifiable; truncated bytes never parsed |
| verified bytes, invalid JSON or not an export doc | `export-document` inconsistent |
| export `cellId` === `cell_id` | binding `verified` (recorded association); configuration lane emitted |
| export `cellId` null or key absent, `cell_id` present | binding `unverifiable`; the report is still emitted (never a failure), the entry cites a pointer that resolves; configuration withheld |
| `cell_id` absent, export `cellId` present | binding `unverifiable`; configuration withheld |
| both present, different | binding `inconsistent`; configuration withheld |
| `snapshot_ids` non-null, equal / differ / export missing | verified / inconsistent / not-recorded |
| `snapshot_ids` null | `export-snapshots` unverifiable |
| export `runtime.id` ≠ trace `runtime.id` | `export-runtime` inconsistent |
| `observation.completeness` vs export `completeness` both present | differ → `inconsistent` |
| export `completeness: "partial"` | configuration entries `partial` |
| declared path outside confinement (`../x`) or an unexpected name | `record-consistency` inconsistent; never resolved or opened |
| a whole upstream-observed run (`cell-real-observed`: real `trace.json`, manifest and observer-produced export) | every `association.*` entry verifies and the configuration lane is emitted from the observer's own export; `execution.model` states no model was requested when the trace records `model.requested: ""` |

### Single-cell content lanes

| Case | Expected |
| --- | --- |
| element `resolved: null` | entry states no resolved layer recorded — not a negative status |
| `interpretation: null` | facets unstated, not "no facets" |
| result.txt / patch states | same recorded/missing/truncated vocabulary as audit |
| supplied v6 doc with matching `run`/`taskDigest` | binding `verified`; verdicts restated, labelled supplied |
| supplied v6 doc for a different run | binding `inconsistent`; verdicts withheld |
| malformed supplied doc | input-level report, not presented as the cell's context |
| structurally incomplete supplied doc (missing spec, context, evidence or provenance) | `unverifiable` supplied entry and binding; no verdict entries |
| supplied v7 comparison to `report-cell` / v6 result to `compare-cells` | the wrong-kind report above; no verdict or transition entries |
| supplied v7 comparison doc | `evaluation.binding` unverifiable (a single-cell report presents only a v6 result); no verdict entries emitted |
| reordered `relations`/`findings` arrays | identical entry ids, order and statements |

### A → B

| Case | Expected |
| --- | --- |
| task/runtime/model/isolation/execution_options mismatch | reject `mismatched-inputs`, exit 3 |
| `requested_cell` absent on one side | caveat, continue |
| profiles differ | allowed; difference recorded as caveat context, not a defect |
| both exports bound, `project.id` differ | reject `mismatched-inputs` |
| one side lacks a bound export — absent, unretained, unparsable, `cellId` null/mismatched, or `cell_id` unrecorded | `comparison.config-unavailable` unverifiable (not-recorded when neither side records an observation), naming that side's binding state; no element/relation/finding diff entries; never "no change"; per-cell lanes unaffected |
| a side's patch record is partial, truncated or uncertified | `comparison.patch` completeness `partial`/`unknown` with the retained-set counts; no per-file entries |
| element only in B / only in A / changed content | added / removed / changed entries, id byte order |
| element resolved in both, status differs | `from`→`to` transition entry |
| element resolved only on one side | counted in newly-effective/no-longer-effective; no `statusChanges` pair |
| reordered `elements`/`relations`/`findings` arrays | identical output (entry ids follow byte-order keys, not array positions) |
| reworded finding | added + removed pair |
| relations added/removed | per-(type,from,to) entries; distinct triples stay distinct even when their concatenations collide |
| the same `cell_id` recorded on both sides | `comparison.cell-ids` says the same id is recorded on both sides — never that the instances are distinct |
| patch blocks with equal `+`/`-` lines at different positions | `changed`, not identical |
| a facet named `__proto__` | a `comparison.facet.__proto__` entry, like any other facet name |
| version notes | each note cites the export field it is about (`data.runtime/version`, `data.resolution/semanticsVersion`, or `data.interpretation`) |
| usage/cost/patch differences | recorded A-vs-B values; no causation |
| A,B vs B,A invocation | A→B direction fixed by flags; deterministic output |
| supplied v7 doc bound / mismatched | as single-cell per side |
| supplied v6 single-run doc | `comparison.evaluation-binding` unverifiable (an A → B comparison presents only a v7 result); no transition entries |

## Fixtures

`test/fixtures/yuurei-cell/` holds one run directory per case. Unless
stated otherwise, its `observation/export.json` is a contract-shaped
record authored for the suite — not bytes produced by pfl or yuurei.

| Fixture | Case |
| --- | --- |
| `cell-a`, `cell-b` | both cells bound; B adds `el_ccc`, removes `el_aaa`, changes `el_bbb` |
| `cell-incompatible` | a different task digest: `compare-cells` rejects with `mismatched-inputs` |
| `cell-observation-unavailable` | the observer failed: no export retained |
| `cell-unobserved` | no `observation` record at all |
| `cell-real-pfl` | **genuine pfl v1.2.0 output**: `pfl export --cell-id cell_20260928T120000Z-a1b2 --json` over a `codex` probe project (schema `2`, 80 observed elements, `completeness: "partial"`, `data.snapshot.cellId` present, 61,733 bytes). Only the `trace.json`/`artifacts.json` records around it are authored; the export bytes and the manifest digest are upstream output, so the reader is exercised against a real v1.2.0 document. |
| `cell-real-observed` | **a whole genuine yuurei v1.2.0 observed run**: `yuurei run probe --observe` under `level1` with a `codex` profile, so `trace.json`, `artifacts.json`, `stdout.log`, `stderr.log`, `patch.diff`, `observation/export.json` and the two `observation/bundle/` files are all upstream output with the manifest digests taken over those bytes. It is the only fixture whose observation record and export were produced by the observer itself, so it exercises the reader against a real `status: "recorded"` run rather than a contract-shaped authored one. It also records `model.requested: ""` (no model requested) and a failed execution (codex exited 1 with no credentials), i.e. a real observed cell whose *execution* did not succeed. |
