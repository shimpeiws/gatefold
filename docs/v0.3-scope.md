# Gatefold v0.3 scope and input contract

This document fixes the v0.3 boundary before implementation. v0.3 adds two
self-contained pfl documents to the existing report input: the full snapshot
from `pfl export --json` and the comparison from `pfl diff --json`. The
contract is grounded in pfl's frozen v1.0 JSON document contract and its
`src/cli/export.ts`, `src/cli/diff.ts`, and core model types (checked
2026-09-26). Gatefold does not execute pfl, inspect a harness, read a path named
inside a document, or depend on pfl at runtime.

## Supported input and dispatch

Gatefold accepts exactly one JSON document, supplied as a file or standard
input. The existing `gatefold <input.json>` and `gatefold -` forms remain;
the input's top-level `command` selects the reader:

| `command` | Required `data` shape | Meaning |
| --- | --- | --- |
| `report` | Existing report shape in [pfl export contract](pfl-export-contract.md) | Aggregate descriptive report (v0.2 behavior). |
| `export` | Full joined snapshot shape below | Observed, resolved, and interpreted element layers plus relations and findings. |
| `diff` | Comparison shape below | One pfl-computed A → B comparison. |

No positional subcommand is introduced. Each invocation consumes one document.
A report, export, or diff can come from a file or stdin; both transports use
identical validation and limits. A leading UTF-8 BOM is tolerated as in v0.2.
A second document, concatenated JSON values, or trailing non-whitespace is
invalid input.

### Common envelope

All accepted commands use pfl's common envelope:

| Field | Type | Requirement |
| --- | --- | --- |
| `pflVersion` | non-empty string | Semver in `>=1.0.0 <2.0.0`; prereleases are outside the range. |
| `command` | string | Exactly one of `report`, `export`, or `diff`. |
| `ok` | boolean | Must be `true`; see failure handling. |
| `completeness` | `complete`, `partial`, or `unknown` | Preserved as observation context. |
| `diagnostics` | array | Required; emission order is preserved. Diagnostic item shape is severity (`info`, `warning`, `error`), non-empty code and message, and optional string path. |
| `data` | object | Required command-specific payload. |

Unknown envelope and payload fields are ignored and never expanded into claim
text. Required known fields with missing or wrong types are rejected. Optional
known fields may be absent only where the pfl shape below says so; explicit
`null` is accepted only where specified. Readers do not coerce values.

A document with `ok: false` is rejected as a failed input. Its `data.error`
code and sanitized message may be included in the actionable input error; the
failure document itself never produces claims. A successful partial document
(`ok: true`, `completeness: "partial"`) is accepted. Completeness is not the
same as command success.

### `export` payload

Required fields and shapes follow pfl's current `ExportData`:

| Field | Shape and meaning |
| --- | --- |
| `project` | `{ id: string, displayName: string }` |
| `runtime` | `{ id: string, version: string|null, adapter: { id, version, runtimeCompatibility: "verified"|"unverified" } }` |
| `snapshot` | `{ observedSnapshotId, resolvedSnapshotId, capturedAt, schemaVersion }`, all strings |
| `resolution` | `{ semanticsVersion: string, confidence: "verified"|"unverified-runtime-version" }` |
| `elements` | Array ordered by `id`; each is `{ id, observed, resolved, interpretation }`. `observed` is required; `resolved` and `interpretation` are required keys whose values may be `null`. |
| `relations` | Array of `{ type, from, to }`; current types are `shadows`, `overrides`, and `accumulates-with`. |
| `findings` | Array of `{ rule, message, elementIds }`. |
| `interpretation` | `{ classifier: { id, version }, origin: "stored"|"recomputed" }`. |

An observed element has `id`, `native: { kind, origin, scope }`,
`source`, `inspectability`, `metadata`, `status`, and optional `reason`.
`native.origin` is one of `project`, `user`, `managed`, `plugin`,
`builtin`, `unknown`; `status` is `observed`, `unreadable`,
`unsupported`, `skipped`, or `unknown`. `source.path`, when present, is
already redacted by pfl and remains data only. Metadata is bounded safe JSON
(string, number, boolean, null, arrays, and string-keyed objects); it is never
turned into arbitrary prose.

A non-null resolved element is keyed by the same `id` and carries
`status`, `activation`, and `resolution`, with optional `applicability`.
Resolved status is `effective`, `shadowed`, `conditional`, `unresolved`,
or `unknown`. A non-null interpretation carries `elementId`, `facets`,
`confidence` (`high`, `medium`, or `unknown`), and `reason`. These
nullable layers mean pfl has no corresponding entry for that element in that
layer; they are not evidence of a negative property. IDs must agree across
the joined element and its non-null layers. Relation endpoints and finding
element IDs are references, not instructions to access external resources.

### `diff` payload

Required fields follow pfl's current `DiffData`:

- `runtime`, `observedSnapshotIdA`, `observedSnapshotIdB`,
  `resolvedSnapshotIdA`, and `resolvedSnapshotIdB`;
- `structural: { added, removed, changed, addedIds, removedIds, changedIds }`;
- `effective: { newlyEffective, noLongerEffective, activationChanged, statusChanges }`,
  where each status change is `{ id, from, to }` and a side may be `null`;
- `facetDeltas`, a record of facet names to signed integer deltas;
- `relations: { added, removed }`, each containing `{ type, from, to }`;
- `findings: { added, removed }`, each containing pfl finding objects;
- `versionNotes`, an array of strings;
- `interpretation: { a, b }`, each side carrying classifier version and
  `origin: "stored"|"recomputed"`.

The structural counts must equal their corresponding ID-list lengths. Counts
are non-negative safe integers; effective transition counts must agree with
the provided status-change records as specified by pfl's diff implementation.
Gatefold preserves A → B direction. It does not join either side to an export
or another diff to reconstruct omitted details.

## Evidence and claim boundaries

Claims distinguish three evidence layers:

1. **Observed fact** — what pfl says it observed, such as an element's
   `observed.status`, `source.path`, or native kind.
2. **Resolved fact** — pfl's static application of runtime semantics, such as
   `resolved.status`, activation, or applicability.
3. **Derived interpretation** — pfl's classifier output, such as facets,
   classification reason, confidence, and findings.

A claim identifies the layer it describes. It must not present a derived
interpretation as a direct observation, or resolution as proof of actual
runtime use. In particular, `effective` means potentially effective in the
static environment; an on-demand skill can be effective without evidence that
an agent used it.

Claim confidence is Gatefold's estimate of how strongly the cited fields
support that exact statement. It is independent of pfl resolution confidence,
per-element classification confidence, and envelope completeness. Those
values remain separate provenance/evidence. An `unknown`, `unverified`,
`partial`, or `recomputed` source limits what a claim can say: do not
upgrade uncertainty to certainty, claim absence from incomplete input, or
treat a recomputed interpretation as a stored fact. Confidence must not encode
whether a harness is good or whether a change is beneficial.

Evidence pointers are RFC 6901 JSON Pointers into the single input document.
Each source field used in a claim is cited; multiple fields may be cited for a
joined statement. Pointers never target a second document, filesystem path, or
URL. The evidence path stays valid even when a value is sanitized for display.
For arrays, Gatefold preserves input order unless pfl explicitly defines an
order; generated claims use a deterministic rule order and deterministic
within-rule order. Export elements are sorted by `id`; diagnostics retain
emission order. Diff relation and finding ordering follows pfl's contract;
other array order is not a semantic guarantee.

### Representative export evidence

Given an export with an observed element at index 0, a shadowed resolved layer,
and a low-confidence interpretation, a supported claim could say:

> pfl observed `agent.md` as a project instruction; its resolved layer is
> shadowed, and the classifier assigned the `instruction` facet with medium
> confidence.

Its evidence must include the actual input locations used, for example:

- `/data/elements/0/observed/native/kind`
- `/data/elements/0/observed/source/path`
- `/data/elements/0/observed/native/origin`
- `/data/elements/0/resolved/status`
- `/data/elements/0/interpretation/facets/0`
- `/data/elements/0/interpretation/confidence`

The statement does not say the file was loaded during an agent run. If the
interpretation is `null`, a claim may say that the export has no interpretation
entry for this element; it may not say the element has no facet.

### Representative diff evidence

For a diff where an element moves from non-effective to effective, a supported
claim could say:

> Between snapshots A and B, pfl reports element `el_123` becoming effective.

Evidence includes `/data/effective/statusChanges/0/id`,
`/data/effective/statusChanges/0/from`, `/data/effective/statusChanges/0/to`,
and the A/B snapshot identifiers used to orient the comparison. A positive
facet delta alone cannot be assigned to a particular element because pfl's
diff does not provide that relationship.

## Text handling and resource limits

Treat the whole document as untrusted input even though pfl redacts its source
paths. Never read a path in the document, fetch a URL, or execute a metadata or
finding value. Sanitize every external string before display or error output:
escape C0/C1 controls, DEL, zero-width and bidi formatting characters, line
and paragraph separators, and U+FEFF as literal `\\uXXXX`. Use bounded
strings for paths, IDs, reasons, metadata, findings, and version notes. Do not
expand arbitrary metadata objects into sentences.

The v0.3 reader applies these ceilings before claim generation (the report
ceilings already documented in [pfl export contract](pfl-export-contract.md)
remain unchanged):

| Resource | Limit |
| --- | ---: |
| Input bytes, file or stdin | 16 MiB |
| Diagnostics | 1,000 |
| Elements in one export | 10,000 |
| Relations in one export | 20,000 |
| Findings in one export | 10,000 |
| Element IDs per finding | 1,000 |
| Total finding element IDs | 10,000 |
| Diff ID lists or status changes, per array | 10,000 |
| Diff relations/findings, per array | 10,000 |
| Repeated/displayed scalar string | 4,096 characters |
| Provenance metadata string repeated per claim | 1,024 characters |
| Nested metadata | depth 12 and 10,000 scalar/object/array nodes per element |
| Emitted claims | 50,000 |
| Evidence references | 100,000 total |

Limits are measured before sanitization and claim amplification. Exceeding a
limit is a deterministic input error; Gatefold must not silently truncate
evidence and then emit a claim that implies completeness.

## Errors and failure behavior

Input failures use the existing CLI exit code 3 and stderr-only error channel.
The v0.2 error codes remain unchanged for report inputs. v0.3 adds stable
codes for the common dispatcher and new shapes:

| Code | Meaning |
| --- | --- |
| `unreadable-file` | The selected input cannot be read. |
| `invalid-json` | The input is not exactly one valid JSON document. |
| `unsupported-version` | `pflVersion` is outside v1.x. |
| `unsupported-command` | The command is not report, export, or diff. |
| `export-failed` | pfl's envelope has `ok: false`. |
| `invalid-shape` | A required field, enum, joined ID, reference, count/list invariant, or limit is invalid. |

Error text is sanitized and bounded. Invalid input produces no partial claims.
Exit code 2 remains reserved for CLI usage errors and 4 for internal failures.

## Versioning and compatibility

- pfl v1.x is the accepted CLI document line. Additive unknown fields are
  tolerated; missing required fields, changed field types, and unknown enum
  values are rejected. pfl 2.x is rejected until its contract is reviewed.
- The output identifies its source with a top-level
  `source: { pflVersion, command }` object. Because the v0.2 result schema is
  closed, v0.3 increments the Gatefold result `schemaVersion` from 1 to 2.
  Schema v2 keeps all v1 claim fields and adds this source discriminator.
  Consumers must branch on `schemaVersion`; old v1 report results remain valid
  v1 documents and are not reinterpreted.
- Existing report input syntax, report rules, claim text, rule IDs, evidence,
  and confidence behavior remain supported. Report JSON output moves to schema
  v2 solely to carry the source discriminator; this intentional version change
  is the only output compatibility break in v0.3.
- Gatefold's own schema follows semver: additive optional output fields within
  a schema version; removal, rename, retyping, or a new required field requires
  a schema version bump.
- Source paths and metadata are data, never access instructions. No claim may
  join multiple input documents.

## Explicit exclusions

v0.3 does not add harness scoring, quality ranking, optimization advice,
root-cause inference, runtime traces, declared-intent comparisons, or joins
across multiple input documents. It describes what one pfl document says and
the relationships that document explicitly supplies.

## Release gate

v0.3 is releasable only when:

- `pnpm ci:all` passes from a clean install;
- real-process file and stdin tests cover report, export, and diff, including
  empty, partial, nullable-layer, malformed, failure, and over-limit inputs;
- claim schema validation, source discriminator, exact pointer existence,
  provenance, confidence separation, sanitization, ceilings, and deterministic
  ordering are verified;
- existing v0.1/v0.2 report fixtures and report input behavior remain covered;
- `npm publish --dry-run` and the installed-tarball smoke test pass;
- package and documentation versions identify v0.3.

The release checklist in [release-checklist.md](release-checklist.md) is the
operational procedure. Issue #28 owns its final update and verification.
