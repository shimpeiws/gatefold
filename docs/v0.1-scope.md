# Gatefold v0.1 scope and acceptance criteria

This document locks the v0.1 boundary. It is the reference for what the first
release does, what it guarantees, and what it deliberately excludes.

## Supported input

v0.1 accepts exactly one input: a `pfl` JSON export file passed as a positional
argument to the `gatefold` command.

The export is a JSON document produced by `pfl` under its `--json` flag. The
exact shape Gatefold accepts — required fields, version range, and unknown-field
handling — is defined by the pfl export contract (issue #3). Gatefold has no
runtime dependency on `pfl`; the export file is the only boundary.

## Output guarantees

v0.1 produces **descriptive claims**: statements about what the export contains.
Each emitted claim carries:

- `evidence` — references to concrete locations in the input representation.
  A claim without evidence is never emitted.
- `provenance` — the source file, the export version, and the transformations
  applied between the raw input and the claim.
- `confidence` — the certainty that the evidence supports the claim. Confidence
  is not a quality score for the harness.

Claims are rendered in two formats:

- human-readable output (default), readable without inspecting JSON;
- machine-readable JSON (`--format json`) that validates against the versioned
  Claim schema (issue #2).

`--min-confidence` filters claims by confidence without changing their contents
(issue #6).

## Excluded features

v0.1 does not include:

- **Declared intent** — claims about what a harness is meant to do.
- **`yuurei` trace input** — observed execution traces are a later input
  boundary.
- **Scoring and quality ranking** — no aggregate score, no ordering of harnesses
  or rules by quality.

## Compatibility policy

- Gatefold accepts `pfl` export documents within the version range declared in
  the pfl export contract; exports outside that range fail with a non-zero exit
  and an actionable error.
- Readers ignore unknown fields, matching the `pfl` document contract. Removing
  or renaming a field Gatefold depends on is a breaking change and bumps the
  accepted range deliberately.
- The Claim JSON Schema is versioned; additive changes keep the schema version,
  structural changes bump it (issue #2).

## Release gate

v0.1 ships only when all of the following pass in a clean `pnpm install`:

- `pnpm typecheck`
- `pnpm lint`
- `pnpm format:check`
- `pnpm test --run` (unit, contract, and end-to-end coverage per issue #7)
- `pnpm build`
- `npm publish --dry-run` succeeds without publishing (issue #8)

These run together as `pnpm ci:all`, which must stay in sync with this list.

## Out-of-scope record

Work recorded here is deferred to a later milestone, not dropped:

- declared intent as a claim category;
- `yuurei` observed-trace input;
- harness scoring, quality ranking, and optimization advice;
- additional input sources beyond the `pfl` JSON export file;
- subcommands beyond the single-input command shape.
