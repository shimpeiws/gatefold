# Gatefold 1.0 public contract and release gate

This document states what Gatefold 1.0 promises, what it deliberately does
not promise, and the executable gate a release must pass. It is the
milestone-v0.11 decision record: the boundary below is frozen only after
the real upstream pair (#83) and the Case A consumer proof (#87) pass
against it. This milestone prepares 1.0; it does not publish it.

## Ownership boundary

Gatefold owns **evidence**: input validation, identity binding,
digest-verified artifacts, audit states, completeness, and descriptive
comparison. The separate `analyze` layer owns contract admission and
verdicts. Gatefold never emits `satisfied`/`violated`, never decides
whether an outcome is good, and never turns a difference into a judgement.

## Public surface inventory and classification

Every published surface is classified: **stable 1.0 contract**,
**historical readable** (still parsed/valid, not the preferred surface),
or **deprecated** (functional but frozen, scheduled for a later major).

### Result vocabulary

| Concept | Contract |
| --- | --- |
| `schemaVersion` + `source.command` | the discriminator pair every consumer branches on |
| claims/entries/facts carry stable ids (`ruleId` / entry `id` / fact `id`) | closed sets, extended only additively |
| `state` ∈ `verified`/`recorded`/`inconsistent`/`unverifiable`/`not-recorded` | the check/record outcome vocabulary (v8–v10) |
| `completeness` ∈ `complete`/`partial`/`unknown` | independent dimension — a verified digest on truncated bytes never implies complete coverage |
| `verdict` ∈ `pass`/`fail`/`unknown` | v6/v7 only — deprecated surface, never recomputed by evidence commands |
| evidence references | `{ source, pointer, digest?, path?, lines?, bytes?, elementId?, note? }` — pointers resolve inside the named input; `digest` repeats a verified stored digest |
| input descriptors | subject/run identity recorded in `inputs` — sufficient to reconcile a report without reloading inputs |

## Locked invariants

1. **Every emitted fact has resolvable provenance**: each claim/entry/fact
   cites `evidence` pointers that resolve inside a named input, plus a
   `provenance.transform` naming the producing command and rule/entry.
2. **Digest-verified stored bytes are distinguished from declared
   values**: a manifest digest attests stored bytes, never authorship;
   declared identities (`cellId`, `source_project`, check-report
   subjects) are self-declarations until a check verifies them.
3. **Missing/partial/corrupt/contradictory/unknown stay distinct**: no
   state collapses into another — absence is never a negative assertion,
   and an unknown layer is never promoted.
4. **An incompatible pair never becomes a comparison**: comparability and
   source-identity gates reject or withhold rather than match.
5. **Static effectiveness never becomes runtime use**: observed or
   resolved configuration is never claimed to have been used by the
   agent.
6. **Difference never becomes quality or causality**: comparisons state
   what differs, with direction and evidence — never which is better or
   what caused it.
7. **Determinism**: identical inputs produce byte-identical results;
   ordering rules are contractual.
8. **Bounds are contractual**: the 16 MiB transport ceiling, path
   confinement, and output ceilings reject rather than truncate or
   silently absorb.

## SemVer policy

Applies to the public surface above once 1.0 ships.

| Change | Version |
| --- | --- |
| New upstream yuurei/pfl fields Gatefold ignores | none (readers already ignore unknowns per contract) or **patch** |
| Additive Gatefold result field (new optional field, new entry/fact id, new optional CLI flag) | **minor** |
| Additive result-field that old readers must not misread (new `state`/`completeness`/verdict value) | **minor** + documented in the scope doc; consumers ignoring unknown enum values must treat them as unknown |
| Changed identity, comparability, or binding semantics — a pair that compared may stop, a binding rule tightens, an id is reinterpreted | **major** |
| Removing/renaming/retyping a result field, removing a command, changing an exit code's meaning | **major** |
| Schema structural change | the result's `schemaVersion` bumps; the old schema file stays published and readable |

Old run/export records: readers keep every documented version working —
a record that no longer validates under a newer reader is reported as
explicitly unverifiable (`invalid-shape` or the per-entry unverifiable
states), never silently reinterpreted.

Deprecated surface: `evaluate-run`/`compare-evaluations` and schemas
v6/v7 are frozen — no new criterion kinds, verdicts, or fields. They are
retained through 1.x and removal is a 2.0 decision
([v0.7 ownership decision](v0.7-scope.md#ownership-and-deprecation)).

## Release gate (executable, before any 1.x tag)

All steps run from a clean checkout of the release commit. The gate
distinguishes authored fixtures (contract-shaped records written for the
suite) from upstream-produced inputs (`cell-real-*` fixtures are genuine
yuurei/pfl output).

1. `pnpm install --frozen-lockfile && pnpm ci:all` — typecheck, lint,
   format, unit/integration tests, build.
2. `npm pack` and install the tarball into a scratch prefix (the smoke
   steps in [release-checklist.md](release-checklist.md) §3–§5 run the
   packed binary on every command, including the deprecated v6/v7 forms).
3. Real-artifact cell checks through the **packed** CLI:
   - `compare-cells` on `cell-real-pair-a`/`cell-real-pair-b` exits 0
     with a `verified` source identity and emitted difference entries;
   - `compare-cells` on `cell-real-run-a`/`cell-real-run-d` emits
     `comparison.config-unavailable` (observation failure), never an
     element difference;
   - `report-cells` on `cell-real-run-a`/`cell-real-run-b` emits the set
     account (`set.inputs`, per-record `set.*` entries);
   - `report-cells` on `cell-real-run-a`/`cell-real-run-d` emits
     `set.config-unavailable`: `cell-real-run-d` is an unbound (unknown)
     contributor, never an absent record.
4. The Case A consumer contract checks of `test/case-a-consumer.test.ts`
   pass — the admitted real pair, missing and disqualified side classes,
   and the mutation that dresses an observation failure as unchanged all
   resolve against genuine evidence with digest-checked citations.
5. Older-schema regression: v1–v8 example documents in
   `schema/examples/` still validate against their published schemas,
   and a supplied v6 evaluation still binds in `report-cell`.
6. `README.md`, `docs/overview.md`, `docs/architecture.md`, the scope
   docs, and `package.json` agree with the boundary above; `pnpm
   format:check` covers doc drift.

Steps 1, 3–5 are exercised continuously by `pnpm test --run` (the e2e and
Case A suites run the packed binary); the checklist exists so a human
release repeats them deliberately on a clean checkout.

## Explicitly outside the promise

- Verdicts on a consumer's proposition (`satisfied`/`violated`) — analyze.
- Proof that an agent used an artifact's contents — Gatefold verifies
  stored bytes and recorded declarations only.
- Contract/predicate evaluation — no DSL exists or is planned in
  Gatefold.
- Execution of upstream tools — yuurei/pfl are input contracts, never
  invoked.
- Stability of `statement`/`reason` prose — consumers use ids, states,
  and fields per
  [the analyze accessor contract](analyze-accessor-contract.md).
